# 判读 - 判官从没判过翻转（"判官一次都没生效"/"从来没人被它拦下"）

> 现象说法：「本地判官好像从来没生效」「它从来没判过翻转」「每次都低置信度人审点名，等于没有」。
> 文件名即索引：判读 + 判官从没判过翻转。

## 触发条件

怀疑本地判官（qwen3-vl 那一层，`[vision]`/DRIVER_VISION 链路）从没起过作用时翻这张卡。
一眼认出的两个数字特征：

1. `references/rotation-dataset.jsonl` 里 `vision_verdict` **只有「正常」和「未判」**，
   从来没有「翻转」/「倾斜」——507 行历史里正常 429 / 未判 78 / 翻转 **0** / 倾斜 **0**，
   而同期用户人工点名翻转 29 段。
2. s08 日志每段都是同一种尾音：`[clip] CLIP 层缺席，VLM 单路；置信度 0.4x < 0.60 → 人审点名`
   —— 全批置信度都卡在 0.60 门槛下，「自动通过」一次也到不了。

查法（一行）：

```python
import json, collections
rows = [json.loads(l) for l in open("references/rotation-dataset.jsonl", encoding="utf-8") if l.strip()]
print(collections.Counter(r.get("vision_verdict") for r in rows))
```

## 首选姿势（可直接抄）

**别在 prompt/参数上继续调，直接换判据**：本地 VLM 的朝向能力天花板已实测为零，
逐帧判翻转的正确做法是 **CLIP 四向旋转搜索探针**（`scripts/clip_probe.py`，
工件 `references/clip-probe.npz`，`infer=rotate_search`）。

单帧验：

```bash
python scripts/clip_probe.py status
python scripts/clip_probe.py predict --image "E:/每日新中国/<日期>/.../_frames/shot05.jpg"
# → verdict=翻转 conf=0.9899 r*=270 frame_rot_deg=90 margin=0.7139
```

产线里探针会自动升主判（driver 加载时看 `rotation_mode`）：

```
[clip] 兜底层在线（hf-hub:timm/vit_base_patch32_clip_224.openai，classes=[...]，形态=rotate_search，thr=0.0）
[clip] 四向旋转搜索形态 → 探针升主判，VLM 转旁证（T10 #119）
```

为什么成立：旋转是**离散**问题（H3 的翻转实测全落在 90° 族），把同一帧按 0/90/180/270
各嵌入一次、取「被判为正立」概率最大的输入 r*，则该帧自身旋转 = (360−r*)，r*≠0 即翻转。
这比「让 VLM 描述朝向」稳，因为比较的是同一张图与自身变换，不依赖模型的语义先验。

## 反面清单（试过不通的）

- **调 prompt**：`vision_common._JUDGE_BODY` 首句断言「这是一张竖屏竖直构图视频的截图」
  等于先把答案告诉模型；即便改掉，4B 仍恒答「下」（12 帧 acc 0.42）。
- **换更大模型**：8B（`--model qwen3-vl-8b`）恒答「上」，acc 0.50——只有正立帧答对，
  任何旋转体都错。8B 不是解。
- **换成相对题**（同帧 0/90/180/270 四张一起问「哪张正立」）：4B acc 0.25 = 瞎猜，
  纯位置偏置（恒答第 1 或第 3 张）。
- **加分辨率/token**：`--image-min-tokens 1024`（ADR 0007 要求，之前实现没兑现）
  补上后 logprobs 分布确实变了（翻转帧 z[翻] 比正常帧高 5 nat），但 argmax 仍恒为「正」——
  **信号在动、决策层仍不翻**，1-D 阈值分不开。
- **调校准温度**：拟合到 40.4（上限 50）后 softmax(z/40.4) 的 argmax 概率结构上封顶 ~0.55
  < `GATE_LO 0.60` → 永远低置信点名，`gate_auto` 永远到不了。降门槛只会放过噪声。
- **零训练 CLIP 质心投票**：recall 0.10 / spec 0.45（假翻转 249）——CLIP 嵌入内容主导，朝向信号弱。
- **单图三分类线性头**：recall 0.72 / spec 0.90，不够。
- 别把 29 个人工点名帧的 90/180/270 朝向也塞进训练——那是把评测真值喂进训练（同场景泄漏），
  能刷到 0.97/0.95 但数字不可信。
- 容易误诊：`dsh_judge.py status` 只查 exe 在盘就报「判官可用: True」，
  而 `[judge]` 层全灭的真因是 **provider 没注册**（`NO_ADAPTER`），探针看不出来。

## 验证方式

- 单帧：`python scripts/clip_probe.py predict --image <人工确认翻转的帧>` 必须给「翻转」且
  `frame_rot_deg` 非 0；再拿一个从未点名帧，必须给「正常」且 `frame_rot_deg=0`。
- 数据口径：`python scripts/clip_train.py --mode rotate4` → 真值 29 帧从不参训，
  期望 recall ≥0.93 / 留出误报 ≤4/125。
- 钉测试：`scripts/test_clip_train.py`（5 节，含「真值不参训」「日期哈希切分」「缺帧丢弃」）、
  `scripts/test_reconcile_clip.py`（3b 节 rotate_search 数学与阈值）。
- 变异验证：把 `clip_probe.predict` 的 `argmax(p0) ` 改回 `argmax(p0[0])`（恒判正立），
  test_reconcile_clip 3b 必须红。
- 端到端：跑一期 s08，日志里必须出现 `[clip] 四向旋转搜索形态 → 探针升主判`。
