# 检查-机械检查报新增违规但本地看着是 0

## 触发条件

新建了 `scripts/*.py`（尤其测试文件），本地 `python scripts/check_mechanical.py` 报
「新增违规 0 处」，**提交并推上去之后 CI 才报红**：

```
[except-pass] scripts/test_xxx.py:372 —— except Exception: ... pass
新增违规 1 处（baseline 未收录，必须修掉或说明后进 baseline）
```

一眼认出：CI 报的违规行号落在**你这次新建的文件**里，而本地同一条命令是绿的。

## 首选姿势（可直接抄）

新文件先 `git add`，再跑机械检查：

```bash
git add scripts/test_xxx.py        # 关键：让文件进索引
python scripts/check_mechanical.py # 这时才扫得到它
```

为什么成立：`check_mechanical.source_files()` 优先走 `_git_files()`，即
`git ls-files -z "*.py"` —— **只扫 git 已跟踪的文件**。未跟踪的 `??` 文件对它不存在，
所以本地永远是 0 新增；一旦 `git add`（哪怕还没 commit）就进了索引，立刻被扫到。
不在仓库里（`_git_files()` 返回 None）时才回退 `os.walk`，那才会扫到未跟踪文件。

## 反面清单（试过不通的）

- 靠「本地跑全量 `run_tests.py` 绿」当保险——`test_mechanical.py` 走的是同一个
  `git ls-files`，未跟踪文件它一样看不见，本地全绿 CI 照红。
- 把违规塞进 baseline（`--shrink`）绕过——违规是真的（`except Exception: pass`
  静默吞异常），进 baseline 等于给以后留个哑弹。
- 以为 `git stash` 能复现——stash 只动已跟踪文件，未跟踪文件仍在盘上但仍在索引外。

## 验证方式

```bash
git add <新文件>
python scripts/check_mechanical.py; echo "exit=$?"   # 期望 exit=0 且「新增违规 0 处」
```

推送后 `gh run view <run-id> --log-failed` 确认 CI 绿。
