# 定时 - 9点报纸任务没产出（别去 schtasks / crontab 找）

## 触发条件

- 「今天 9:00 的报纸怎么没出来？」「`E:/每日新中国/<日期>/` 目录整个不存在」。
- 想查定时任务，但 **Windows 任务计划程序里没有、WSL `crontab -l` 也是空的**。
- 现象特点：目录不是「跑一半失败」（那会留下 `0新闻_粗筛.md`），而是**完全不存在**。

一眼认出：仓库文档（`AGENTS.md`）里写的「9:00 定时任务」在系统层根本不存在，
真正接的是 **DSH 任务板卡**，所以 `schtasks /query` 和 `crontab -l` 必然一无所获。

## 首选姿势（可直接抄）

看卡片台账（唯一真源）：

```
C:\Users\LMR\.dsh\task-board\ledger-v2.json
```

```python
import json, datetime
d = json.load(open(r"C:\Users\LMR\.dsh\task-board\ledger-v2.json", encoding="utf-8"))
for t in d["tasks"]:
    s = t.get("schedule") or {}
    print(t["title"], "| enabled=", s.get("enabled"), "| cron=", s.get("cron"),
          "| lastTriggered=", s.get("lastTriggeredAt"), "| next=", s.get("nextRunAt"))
    for e in t.get("executions", []):
        print("   ", e.get("startedAt"), e.get("result"), "|", e.get("error"))
```

判定只看 `executions[]` 的 `result` / `error`：

| error 文本 | 含义 | 处置 |
|---|---|---|
| `workspace not found: <uuid>` | 卡片绑定的工作区已失效 | **重建卡片**（改代码没用） |
| `agent turn ended without completing: interrupted` | 跑到一半被中断 | 看那次 session 日志 |
| `agent turn ended with an error` | agent 侧报错 | 看 session 日志 |

时间戳是**毫秒**，且 `startedAt` 为 UTC；换算本地：`new Date(ms + 8*3600e3)`。

补充证据源：`E:/每日新中国/archive/articles/2026-MM.jsonl` 的 `date` 字段——
**哪个日期有归档记录，就说明那天管道真跑过**。缺的日子在两处都空，等于从未启动。

## 反面清单（试过不通的）

- `schtasks /query` 找 `daily|china|每日`：零命中（已实测）。
- `Get-ScheduledTask | Where Actions -match 'run_all'`：零命中（已实测）。
- WSL `crontab -l`、`systemctl list-timers`：只有系统自带的 dpkg/logrotate，无报纸任务。
- `E:/每日新中国/logs/cron-<日期>.log`：**只是历史遗留文件**，仓库里已无任何代码写它，
  最近一份停在 2026-10-14；用它判断「今天跑没跑」会误判。
- 别急着去补跑历史日期：采集是「抓当天首页」，补跑 `--date 2026-10-16` 只会把**今天**的新闻
  记到 10-16 名下，日期与内容错位。

## 验证方式

- 读 ledger，目标日期的 `executions[]` 里应有一条 `startedAt` 落在当天 09:00±1min、`result="completed"`。
- 交叉验：`E:/每日新中国/<日期>/3新闻_概述.md` 与 `archive/articles/2026-MM.jsonl` 里该日期记录同时存在。
