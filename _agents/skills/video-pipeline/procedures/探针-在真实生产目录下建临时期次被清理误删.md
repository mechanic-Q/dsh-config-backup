# 探针-在真实生产目录下建临时期次被清理误删

## 触发条件

写「真实路径探针」验证生产行为时，为了让生产的缺省根能扫到，**在真实生产根下
（如 `E:\每日新中国\`）`os.makedirs` 造了一个日期目录**（`2026-10-20\...`），
收尾用 `rd /s /q <那个日期目录>` 清理。

一眼认出：探针里出现 `os.path.join(<真实生产根>, <日期或期次名>)` + `os.makedirs`，
且 finally 里 `rd /s /q` 的目标是**含日期的层级**而不是你自己起的唯一名字。

## 首选姿势（可直接抄）

在真实根下**只建一个自命名隔离目录**，期次造在它里面：

```python
PROBE_ROOT = os.path.join(real_root, "_182probe")   # 第一层就是自命名，glob 的 * 照样命中
slug = os.path.join(PROBE_ROOT, "video", "每日新中国b站", "流水线", "_182verify")
...
finally:
    assert os.path.basename(PROBE_ROOT) == "_182probe"   # 删前核实目标
    subprocess.run(["cmd", "/c", "rd", "/s", "/q", PROBE_ROOT], ...)
    # 复查日期目录一个没少
    left = [d for d in os.listdir(real_root) if os.path.isdir(os.path.join(real_root, d))]
    assert os.path.isdir(os.path.join(real_root, "2026-10-19"))
```

为什么成立：生产扫描的 glob 是 `<root>/*/video/*/流水线/*/_frames/evidence/manifest.json`，
`*` 对第一层无差别匹配——自命名目录和生产日期目录在扫描口径上等价，
所以隔离根**不影响验证真实性**，却把删除范围锁死在一个你自己起的名字上。

## 反面清单（试过不通的）

- 用真期次名（`2026-10-20`）当探针容器——万一同一天真跑过生产，`rd /s /q` 直接毁当天产物；
  Windows `rd /s` 不进回收站，删了找不回来。
- 「反正数据集里没有这期，删了也没事」——数据集没行 ≠ 目录里没东西（生产可能只跑到中途）。
- 只靠 `try/finally` 就以为安全——finally 里的删除目标本身才是风险点，跟有没有 try 无关。

## 验证方式

探针跑完检查两件事，缺一不可：
1. 自建根已消失：`os.path.isdir(PROBE_ROOT) == False`
2. **日期目录一个没少**：`len([d for d in os.listdir(real_root) if d[:2]=="20"])` 与跑前一致，
   且最近真实期（如 `2026-10-19`）仍在。

误删后的取证路径：数据集有无该期次行 / `E:` 盘最新日期目录 mtime / 回收站 / 全盘引用搜索。
