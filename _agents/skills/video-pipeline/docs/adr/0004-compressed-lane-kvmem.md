# ADR 0004：压缩车道——s04-s07 四阶段前置防线转移至生成期约束 + 后置防线

> **⚠️ 后端选型已被取代（2026-10-12）**：压缩车道本地服务从 KVMem（WSL 18201，IQ2_S）
> 切至 Strata（Windows 主机 8080），生命周期托管随 [ADR 0006](0006-strata-backend-and-window.md)
> 重落（conflict 分段起停；KVMem/8888 体系整体退役）。本 ADR 的**车道二分**与**质量
> 兜底转移**设计仍然有效；文中 KVMem/8888/18201 细节为历史记录，勿按现状理解。

- 状态：已接受（2026-09-24，grilling 会话定案；票1 #58 / 票2 #59 / 票3 #60 落地，票4 #61 首测校准）
  ——后端选型部分已被 [ADR 0006](0006-strata-backend-and-window.md) 取代（2026-10-12）
- 上下文：读报单 s04-s07 四个文字设计阶段（导演/摄影/美术/H3 转译）占端到端 169 分钟的
  六成（0922 台账 101.4min，其中 s07 单镜串行 51.4min），且每期需人工起停 8888 服务、
  每期手动轮转。KVMem + IQ2_S（WSL）实测 49.8s 单次调用产出 16 镜全部合规的 H3 prompt
  （79-86 t/s），为全部受测路线最快。但单次调用意味着四阶段链上的中间产物消失——
  七项自检、枚举纠偏、横移配额纠偏、交接卡等**前置防线**随中间设计稿一并失效。

## 决策

1. **车道二分**：`compressed`（默认）= s04-s07 压成对本地 KVMem 实例的单次 LLM 调用，
   直出 06_H3prompt 全量产物；`legacy` = v3 四阶段链原样保留为显式回退开关
   （--lane legacy / DRIVER_LANE）。切换车道自动清 s04-s07 stamps（两车道产物语义不同）。
2. **质量兜底转移**（本 ADR 核心记录，后人问"为什么敢砍四阶段防线"的答案）：
   - 生成期约束门：竖屏约束句/旁白句/反模板/横移配额从「事后自检+纠偏」改为 SYSTEM
     提示词生成期硬约束 + 落盘前 enforce_constraints / sanitize_camera_text 代码级收口
     （约束句由代码注入，占位符原样外发=模型无法遵守，0924 实测教训）。
   - 结构契约：rec 四字段（id/prompt/video_seconds/portrait_risk/camera_sanitized）+
     整单原子落盘（.tmp 原子替换、ID 集合完全一致才写），代替中间稿的多级校验。
   - 后置防线不变：vision 三级判读 + 删除式消毒/竖直化重写梯队（s08）、九宫格 +
     确认门④人审（旋转终审）。时长权威 = TTS 实测 duration_est。
3. **服务窗口托管**（票3）：KVMem 生命周期归 driver 全自动——s04 入口自动启动
   （8888/残留清理 → 拉起 → /health → 冒烟 gen_tps ≥40 放行；阈值为客户端口径，
   票4 0925 校准：冷启首测 ~50、稳态 58-86、劣化态 4，与劣化态保持 10 倍距），
   s08 入口自动卸载（pkill + 显存回落确认才放行烧卡），跨期不驻留。窗口内异常走
   自愈阶梯不叫人：清理 → 重启复测 → 挂死重启重发，硬边界 2 轮完整重启循环；
   WSL 级故障只试一轮，不做 wsl --shutdown 重拳。8888/start_qwen.sh 保留
   （np4 吞吐位）仅退出日常流程。
4. **preflight 扩展**：压缩车道开跑前静态拦截 WSL 不可执行、KVMem 运行包/模型缺件
   （fail-fast）；显存水位与 8888 冲突为预警不拦截（动态状态，窗口入口硬查+自动处置）。

## 后果

- 文字段 101.4min → ~2min（单次调用 + 窗口起停），端到端预期 -59%；8888 每期手动
  起停环节消除。票4 #61 实测：文字段 1.7min（IQ2S）/ 2.95min（GSQ），16/16 一次通过。
- 设计多样性统计（景别分布/横移占比台账）与旋转数据集 design 侧特征随中间稿失效，
  门④摘要不再展示；防线重心移到生成期与生成后，风险由门④人审兜底。
- 被否方案：v3 脚本链直打 KVMem（指南红线 #4：量化模型契约连败——单镜 12+ 连败、
  photographer 空表；叠加红线 #1 单实例会话请求预算 ~20 轮，约 30 轮后解码劣化
  4 t/s 且输出变坏——48+ 次请求的 v3 链必然撞墙，不可行）；混合车道（s04-s06 云端
  + s07 本地等分阶段混搭）——8888 与 KVMem 显存互斥（红线 #3）定死同机只能容一个
  27B 实例，s04-s06 留云端则 429 限流与四阶段中间稿耗时照旧、最大单点 s07 只省一半
  不到，且前置防线本就耦合四阶段中间稿，混搭两头不靠；单镜缺失补洞（单次 ~50s，
  整单重调更便宜更稳）；静默回退云端（违反环境预检哲学，回退必须走 legacy 显式开关）。
- 落点：kvmem_h3_lane.py（车道核心）、kvmem_window.py（窗口+自愈）、run_pipeline.py
  （_gate_kvmem / s08 入口关窗 / 连败 restart_cycle）、preflight.check_kvmem_static。
