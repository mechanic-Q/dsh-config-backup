# ADR 0003：枚举级纠偏——违反硬自检时 driver 可自动改写设计层闭合枚举

- 状态：已接受（2026-09-22，用户拍板）
- 上下文：导演设计（s04）产出的「景别」枚举偶发相邻硬重复（2026-09-21 期 shot10→11 中全景×2、
  shot12→13 大全景×2），触发七项自检⑦连败死锁。故障手册明示"摄影师不重抽景别，重试不可能自愈"
  （0908 实证），官方恢复路径是人工手改 `03_导演设计/shotXX.json`——实测一次死锁烧约 10 分钟
  等待加人工。"摄影师无权改景别"的铁律针对的是**内容语义**被下游悄悄改写，不是枚举值本身的相邻冲突。

## 决策

1. **权界二分**：设计层字段分两类。语义字段（场景/情绪/镜头/信息点）＝导演专属，任何下游环节
   不得改写；**闭合枚举字段（景别、节奏等有合法枚举集的字段）**在违反自检硬校验时，允许 driver
   做最小自动纠偏。
2. **纠偏规则**：只处理相邻硬重复；只改冲突对中靠后的一段；新值取「与前后镜都不重复的合法枚举中、
   与原值尺度距离最近者」；每次纠偏写台账（`report.json`）+ 日志留痕；纠偏后重跑七项自检一次，
   仍失败叫人。
3. **先例一致性**：与运镜消毒（ADR 0001 体系）同构——都是"保内容权威、动执行层句式/枚举"，
   且都走台账留痕可审计。

## 后果

- 死锁从人工恢复变自动恢复，s05 不再因⑦连败退出叫人。
- 导演的画面意图（镜头语义描述）不被触碰；纠偏率入台账，可逐期统计验证。
- 被否方案：喂回导演 LLM 带约束重抽——贵、慢、可能引入新设计漂移，且人工路径早已拍板"手改字段"，
  自动化只是把该路径变自动。
- 落点：storyboard_enhancer ⑦ 检查处暴露纠偏候选项，driver s05 阶段执行纠偏并重检（具体摆放
  由实现票定）。
