# ADR 0005：无人值守入口与环境拉起——入口层自己把环境拉到位，环境预检保持 fail-fast

- 状态：已接受（2026-09-25，grilling 会话定案）
- 上下文：每日 9:15 cron 入口首跑当日即被环境预检拦截——Windows 侧 ComfyUI 未运行
  （127.0.0.1:8188 无监听；18188 仅为 portproxy 在听，测 18188 会假通）。「环境预检」
  的语义是 fail-fast 叫人（见 CONTEXT.md），它假设现场有人接住并重跑；无人值守场景
  "叫人" = 一条飞书消息 + 当日停摆，人工往返打断自动化闭环。同一首跑另实锤两个入口
  层缺陷：裸 `nohup setsid … &` 随 `wsl -e` 会话退出被连坐杀死（`$!` 有值是假象，
  连日志文件都不生成）；pgrep 不用括号防自匹配会把检查命令自身算进去误判。
  用户实证：ComfyUI 可脱离绘世启动器直接拉起且"程序多次自己拉起过"（2026-09-25 确认）。

## 决策

1. **职责边界**：无人值守入口（每日 cron 通道）own「环境拉起」——前置检查（上游
   任务已结束、当日输入就绪）→ 环境拉起 → 脱离启动 driver。环境预检语义不变：它
   假设环境已被拉到位，只对拉不起来的事 fail-fast 叫人。
2. **拉起阶梯（放弃当日是终态，不是首反应）**：在线探测必须用后端口径（Windows 侧
   127.0.0.1:8188/system_stats，不信 18188 转发面）→ 不在线则整合包直启
   （python\python.exe main.py --listen 0.0.0.0 --port 8188，日志落 logs）→
   10 分钟就绪等待 → 复查窗口共 60 分钟（覆盖被人工启动的分支）→ 彻底失败才发
   飞书并放弃当日。放弃 = 通知根因与人工修复路径，现场原样保留（stamps 不动），
   当日人工重跑接续。
3. **启动加固为入口层标准形态**：WSL 后台启动必须 `< /dev/null` + 父进程 sleep
   观察窗 + 日志落地校验；进程探测一律 `[r]` 括号写法防自匹配。
4. **确认门等待按场景分档**：无人值守每日任务用 `--gate-timeout 28800`（8h：
   成片上午出、当天审当天发）；默认 3600 保留给交互场景。
5. **红线不变**：入口层不代用户做任何确认门决策（绝不乱用 --gate-approved）、
   不并行流水线（16G 显存互斥）。ComfyUI 空闲几乎不占显存、不在报纸互斥清单
   （8888/8899/18200/18201）内，先拉起无害。

## 后果

- 无人值守闭环成立："ComfyUI 忘开"从当日停摆等人变为入口层自愈项；仍不可恢复时
  只剩一次人工往返（看通知 + 重跑一条命令）。
- 代价：定时任务自动启动 GPU 服务（headless），故障面扩大。缓解：启动日志落
  logs/comfyui-<日期>.log(.err)，放弃通知附日志尾部；入口层顺序执行（等报纸结束
  → 查概述 → 拉 ComfyUI → 启动 driver），不与上游抢显存。
- 被否方案：仅等待不拉起（首跑已证明"忘开软件"是常态而非例外，纯等待白丢自动化）；
  Windows 开机自启 ComfyUI（常驻范围过大，与错峰/按需的显存纪律相悖）；入口层吞掉
  环境预检拦截自动放行（违反 fail-fast 哲学）。
