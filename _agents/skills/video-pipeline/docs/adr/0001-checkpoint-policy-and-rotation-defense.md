# ADR 0001：检查点集中在进 GPU 前 + 旋转用「预防+人审」而非自动检测

- 状态：已接受（2026-09-05，用户拍板「检查点少而精、集中最必要处」）
- 上下文：0904 跑单 qwen 生成 4/23 段 prompt 失败但校验放行，缺段被推迟到 H3 烧完 45 分钟 GPU 才暴露；
  同期成片混入 4 段 90° 旋转镜头。跨三跑单分析（references/rotation-analysis-20260905.md）证实
  横向行进运镜为旋转高危共性，且几何检测器与可用 VLM（glm-4.6v，4 种提示词策略）均无法可靠判定旋转。

## 决策

1. **LLM 生成失败视为常态**（采样随机性不可根除），但错误逃逸到 GPU 阶段必须 100% 拦截：
   - 源头自愈：s6 脚本内失败段立即补跑一轮，仍失败 exit 1（driver 不再信任 rc==0 即成功之外的语义）。
   - 唯一硬对账门：prompt ID 集合 == raw 段 ID 集合，设在 s6 出口与 s9 烧卡前；毫秒级文件检查，零 LLM 成本。
   - 不新增任何 vision/LLM 型检查点。
2. **旋转防疫走预防而非检测**：
   - s6 生成端横移运镜门（高危特征 5/5 命中）：禁横移重试 → 句级消毒（只动运镜句，保画面丰富性）。
   - 人眼终审：确认门④强制附镜头九宫格；vision 判读降级为辅助信号（失败重试后留痕，不阻塞、不放行）。
   - 放弃：几何自动检测器（负结果已记录）、把 vision 判读失败当硬失败（对不可靠信号硬失败只会制造假停机）。

## 后果

- 好处：qwen 瞬时失败在 1–2 分钟内自愈，对 agent/人不可见；缺段/缺尾段不可能再进 GPU；
  旋转镜头在生成前即被消毒，良好镜头丰富性不受损；台账常开，优化有据。
- 代价：横移门会消毒约 1/3 含横向词的镜头中的一部分（仅运镜句，场景保留）；vision 判读成本保留但降级。
- 反悔成本：若未来接入可靠旋转检测器（更强 VLM 或本地视觉模型），只需替换 s9 梯队的触发信号，阶段契约不变。
