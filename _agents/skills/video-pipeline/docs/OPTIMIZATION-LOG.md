# 优化演进史（OPTIMIZATION LOG）

> **一句话**：这套工具把「B站读报视频」的生产从 **盯着一整晚、耗一亿 token**，
> 进化到 **一条命令、一顿饭工夫自动出片、消耗降一个数量级**——而且每次事故都会变成一道新防线。

本文是给「想快速了解这套工具进化速度」的人看的。节点式记录每次大版本改了什么、
优化了多少、数据从哪来。逐期运行数据在文末台账，随每期跑单追加。

## 一、核心指标演进（10 秒版）

| 维度 | v2 · agent 模式（9/2–9/3 实测均值） | v3 · driver 模式（9/5 实测） | 提升 |
|---|---|---|---|
| ⏱ 单支视频总耗时 | ~17.7 小时（过夜盯流程） | ~3.3 小时（自动跑，还含 3 个现场 bug 修复） | **快 5.4 倍（−81%）** |
| 🪙 大模型令牌总消耗 | ~1.0 亿 tokens / 支 | ~1,490 万 tokens / 支 | **省 85%（6.7 倍）** |
| 💰 真实输入令牌（计费大头） | ~242 万 / 支 | ~12.4 万 / 支 | **省 95%（20 倍）** |
| 📞 模型 API 调用次数 | ~430 次 / 支 | ~166 次 / 支 | −61% |
| 🖐 人工介入 | 全程参与 + 多次等待 | **发布前审一次**（成片+封面+九宫格一次看） | 从「盯全程」到「点一次头」 |
| ⚡ 提示词生成阶段 | 云端 DeepSeek 22 min / 20 镜 | 本地 qwen3.8 **10 min / 20 镜** | 快 2.2 倍，**API 费用归零** |
| 🚨 缺镜头事故 | 烧完 45 分钟 GPU 后才发现 | **进 GPU 前毫秒级拦截** + 脚本内自愈 | GPU 浪费归零 |
| 📐 画面旋转流入成片 | 4 / 23 段（发布后才发现） | 生成前消毒 + 发布前人工九宫格终审 | 事后救火 → 事前预防 |

> 口径说明：耗时/令牌为同一条产品线（每日读报视频）端到端生产会话的实测值，
> 来源 Hermes `state.db`（sessions + session_model_usage 表）。v3 的 3.3h 包含当天 3 个
> 现场 bug 的排查修复，纯跑单耗时应更低；v2 的 17.7h 包含人工闸门等待。

## 二、演进节点

### 节点 0 · 骨架期（2026-08 下旬，`fa39587`）
9 阶段 skill 骨架 + 确认门 + 硬约束。全流程 agent 手工驱动，每条 ffmpeg 都过一遍模型。

### 节点 1 · 能力建设期（2026-08 下旬，PR #1–#5）
- Krea2 数字迷幻封面、纪实卡通风格、读报旁路模式（`aff3e70`：跳过阶段零，稿子直进）
- E2 配音模仿配方（`2799323`）
- **竖屏方向约束制度化**（`409f298`，P0）：生成注入 + 自动补齐 + 独立检测——第一次把「画面旋转」从事故变成防线
- **S1–S7 结构化重构**（`d916a91`）：全部环节产物 JSON + schema 强校验 + 交接卡 + 并行——「自由文本」变「机器契约」，为后来一切自动对账打地基

### 节点 2 · v2 agent 模式成熟期（2026-09-01 ~ 09-03）
每天能出片了，但代价清晰可见：**单支 71–127M tokens、16.5–18.9 小时、数百次模型调用**。
同期修复一批质量事故：BGM 响度/报纸段装配、封面降级禁令、`_imd_ok` 拦截模板复制（PR #26）等。

### 节点 3 · 本地模型决策（2026-09-03，#29 质量测试，`_test/qds/REPORT-29.md`）
四臂对照实验（20 镜，三阶段全跑）：

| 方案 | 用时 | 结论 |
|---|---|---|
| 云端 DeepSeek-V4-Flash | ~22 min | 质量达标，有 API 成本 |
| **本地 qwen3.8-27B（关思维链）** | **~10 min** | **快 2.2 倍；S6 提示词阶段快 3.8 倍；零 API 费** |
| 本地 qwen（开思维链） | ~78 min | 慢 7.8 倍，截断风险高，否决 |
| qwen + 决策表注入 | ~27.5 min | 质量增益不抵耗时，按需启用 |

**决策**：阶段 4/5/6 默认本地 qwen 关思维链。省钱 AND 提速，双赢。

### 节点 4 · v3 driver 化（2026-09-04，PR #34，wayfinder #28–#33）
**一条命令全自动编排**：口播稿 → TTS → 分镜 → H3 → 字幕 → 封面 → 飞书确认门 → 三平台发布。
- 确认门从多个合并为 **发布前审一次**（成片+封面+九宫格）
- stamps 断点续跑：任何阶段失败修完重启，不重复烧 GPU
- 每阶段自动重试 1 次，连败飞书叫人
- **效果**（对比节点 2）：总耗时 −81%，令牌 −85%，人工从全程盯 → 审一次

### 节点 5 · 防疫体系 + 内容升级（2026-09-05，PR #36）
9/4 期跑单暴露两类事故：qwen 生成 4/23 段提示词失败但放行（烧完 45 分钟 GPU 才发现）、
4/23 段画面 90° 旋转进入成片。跨三期数据的系统分析（`references/rotation-analysis-20260905.md`）
找到共性后，建立：

1. **进 GPU 前硬对账门**：产物 ID 集合必须等于分镜段集合——缺镜头在毫秒级被拦，不再烧完 GPU 才爆
2. **源头自愈**：失败镜头脚本内立即补跑（1–2 分钟，对人和 agent 都不可见），不再谎报成功
3. **横移运镜门 + 消毒**：5/5 实锤旋转镜头的共性是「横向行进运镜」；检出即禁横移重试，
   仍命中则只消毒运镜句（场景/光线/声景保留）——旋转高危在生成前治愈
4. **九宫格人审**：vision 判读对本风格不可靠（4 种提示词实测负结果已存档），旋转终审交给人眼，
   确认门自动附全段缩略图
5. **内容升级**：取消人物/近景一刀切禁令，改为「台词讲人→人物镜头；讲宏观→空镜」的逐段智能判断
   （ADR 0002）；同时用数据逼出导演模板病——0904 期 23 段设计 100% 是「横移长卷」，已加反模板约束
6. **常开台账**：每期跑单自动写 `_driver/report.json`（各阶段耗时/重试/消毒/判读/景别分布），
   本文档的「逐期台账」从此自动有源

### 节点 5b · 视听细节用户定制（2026-09-05，同 PR）
- 翻页过渡音效：白噪声合成 → 真实翻书录音（用户从 7 个 CC0 候选选定「Page Turn, Big Book」）
- 字幕/标题字体：思源黑体 → **得意黑 Smiley Sans**（用户从 6 款免费商用字体对比选定，OFL 可商用）

### 节点 6 · 质量根治 + 编号统一 + 执行提速（2026-09-07 ~ 09-08）

三个带病发布 bug 根治（0907 凌晨全链逐段测试发现）：新闻稿编辑占位行三层剔除
（0906 成片曾把「栏目留空」念出来）、H3 prompt 补 [Shot] 编号唯一递增+时间戳
上限两道门、整体方案/交接摘要改走 JSON 强校验通道（low 组合把思维链写进
content，两处产物带推理泄漏）。

**编号统一**：driver 阶段号与目录号配对归位（s01 分段 → s13 发布，纯整数），
旧 stamps 自动迁移；存量 12 个项目一次性迁移（`migrate_project_dirs.py`）。

**七项优化**（逐项实测）：导演【镜头】结构化（景别/运镜枚举）+ 横移确定性
配额——prompt 软约束四轮实测 58–84% 超标，配额后 **10%**，运镜 6 类全用；
s07 重试三级熔断（连败退化 96字→8字 实证）；方向锁（重跑不漂移）；IMD 输出
瘦身（−12%）；并发可调；token 台账；失败预览常开。

**0906 歪镜头事故根因治理**（发布后人工发现 4 段 90° 翻转）：根因是产物完成
状态存了两份（driver 看文件、submit_accel 看 jsonl），重生成删了产物仍被
jsonl 记录 SKIP。根治为**产物状态单一事实源**（产物文件唯一判据，jsonl 降级
审计）；重生成三级梯队（双采样 → 按因竖直化重写 → 运镜消毒，shot19 实战：
原样×2 败 → 重写一次成）；vision 并行化（22 段 2-3h → **51s**，并行重判
当场抓到 0907 shot19 漏报）；同卡互斥守卫前置烧卡入口（qwen 常驻致 H3
87s/段 拖到 6min/段，0907 期 132min/22段 实锤）；交接卡补位（driver 从未
调用 gen_handoff，五路汇聚首次完整）。

### 节点 7 · preflight + 压缩车道 + 测评收口（2026-09-22 ~ 09-25）

**preflight 环境预检**（0922，#46）：启动即拦截环境故障——0921 期 CRLF 让 s05
连败退出时 s01-s04 已烧 45 分钟，护栏必须在烧钱前叫人（CRLF / bash -n /
ComfyUI / 飞书凭证 / 必需资产 fail-fast + 排障指引）。同期 ADR 0003：s05 景别
死锁枚举级纠偏（0922 retro 定案）。

**压缩车道**（#57-60，ADR 0004）：s04-s07 四个文字阶段压成对本地 KVMem
（Qwen3.8-27B IQ2_S，WSL）的**单次 LLM 调用**直出 06_H3prompt——0922 分支
实测 49.8s 出 16 镜全合规（解码 79-86 t/s），取代 31 次调用 ≈358K prompt 的
v3 四阶段链；driver 全自动托管 KVMem 窗口（s04 入口显存水位硬查+自动起服
+冒烟放行，s08 入口自动卸载，自愈阶梯 2 轮硬失败叫人），8888 每期手动起停
环节消除；旧链保留 `--lane legacy` 显式回退。

**首测评收口**（#61-#62 + #55，0925）：0922 期副本不烧卡对照——文字段
**101.4min → 1.7-3.0min**，cam_3elem 56% 贴线由门④人审兜底，拍板默认 IQ2S
（GSQ 档第一备选、同档重试×2 才叫人、5min 天花板仅测评口径）；过程中修复两个
窗口缺陷：probe_tps 客户端口径兜底（KVMem rc1 无 timings 字段，SMOKE_TPS
校准 50→40）、spawn 改 WSL 内 setsid 直拉（嵌套 wsl.exe 会杀守护进程）。
文档三线收口：pitfalls #45-47、SKILL.md 模型分配表/用法、SKILL.md 浮出
`--gate-approved`（确认门 agent 批准路径：飞书轮询过滤 bot 自发消息→代发
「通过」无效，用户会话内明确批准后带参重启，stamps 保留直接进发布）。
第二层验收（生产实战：s08 翻转率 vs 基线 1/16、门④改稿量）待下一期。

## 四、方法论：这套工具怎么持续变强

1. **事故 → 防线**：每个发布事故（旋转、缺段、字幕越界）都固化为代码级检查，同型问题不再复发。
2. **能写成检查的，不指望模型自觉**：LLM 生成天然有随机失败率，但对账门保证错误永远逃不出进 GPU 前。
3. **数据先行**：report.json 常开台账 + state.db 口径统一（总令牌/墙钟），每次优化都有前后对照，
   本文档随每期跑单生长。
4. **实验决策**：换模型/换参数先跑对照实验（如 #29 四臂对照），用数字拍板而非感觉。
