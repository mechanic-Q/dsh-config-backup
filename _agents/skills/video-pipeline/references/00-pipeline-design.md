## 三、模块化与解耦设计

### 3.1 项目文件夹结构（每环节独立目录，互不污染）

```
<稿子目录>/（唯一锚点）
├── <稿子>_口播稿.md              ← 阶段1产出（唯一输入锚点）
├── 480P/                         ← H3 分段视频（稿子同级，永不删除）
├── 流水线/<slug>/
│   ├── 00_口播稿/                ← 阶段1：定稿 + 幕表 + 来源
│   ├── 03_导演设计/          ← 阶段2：创意方向卡 + 整体视觉方案 + 交接摘要
│   ├── 03_导演设计/          ← 阶段3：读 01 → raw.json + shotXX.md 逐段设计
│   ├── 04_分镜增强/              ← 阶段4：读 02 → enhanced.json（8字段）
│   ├── 04_口播台词/              ← 阶段3 提取：纯台词（给TTS）
│   ├── 06_H3prompt/              ← 阶段5：读 02+03 → prompt_XX.json
│   ├── 02_TTS语音/               ← 阶段6：读 04 → audio_XX.mp3
│   ├── 07_成片/                  ← 阶段7：读 05+06 → 最终成片 + verify报告
│   ├── 08_字幕/                  ← 阶段8：读 07 → 字幕.srt + 烧录版
│   ├── 09_封面/                  ← 阶段9：读 00 → 海报 + 标题方案
│   └── 10_发布/                  ← 阶段10：读 07+09 → 核验报告
└── 发布/                         ← 阶段10：各平台核验证据
```

### 3.2 解耦原则

1. **阶段间只传文件，不传状态**——每阶段产出落盘 JSON/MD，下一阶段只读文件。改任何阶段不动其他阶段代码。
2. **脚本单职责**——每个脚本只做一件事（分段/增强/生成/合成/字幕/封面），输入输出都是文件路径。已有 30+ 脚本全部复用。
3. **方法论与执行分离**——references/ 管"怎么做好"（LLM 判断用），scripts/ 管"怎么做"（确定性执行），SKILL.md 管"先做啥后做啥"。
4. **共享方法论目录**——`references/video-craft/` 放跨系统复用的方法论（导演/分镜/美术/情绪/镜头语法），本 skill 和 OpenMontage 都通过 context pointer 指向，单一源。
5. **可旁路**——用户只要单个资产时走快捷路径（只要口播稿/只要分镜/只要prompt/只要成片），不强制全流程。
6. **新增环节即加文件夹**——如未来加"多语言配音"就加 10_多语言/，不动现有 0-9。

## 四、审核与检验机制（三层）

### 4.1 每阶段自检门（阶段内，自动执行）

| 门 | 阶段 | 检查项 |
|---|---|---|
| ① | 零（口播稿） | 黄金三秒：第一句=钩子、禁铺垫式开场；信息点每2-4s一个；落点落情绪不落知识 |
| ② | 一A（整体视觉方案） | ①方向卡 2-3 可选 ②整体方案六要素齐全（主线/场景/母题/色彩/节奏/衔接）③交接摘要≤15行 |
| ③ | 一B（逐段视觉设计） | 时长覆盖：①每段≤15s ②Σ(段时长)≥台词总时长/4.5 ③每段有情绪基调 ④每段有信息点 ⑤专有名词未拆开 ⑥对齐整体方案 |
| ④ | 二（分镜增强） | 七项：①时长≤15s ②节奏意图合法 ③连续性链成环 ④Hook分布（首尾强+每3段1强）⑤有信息点 ⑥镜头类型+秒级指令合法 ⑦景别交替（上镜末景别 vs 下镜首景别不重复） |
| ⑤ | 四（成片） | verify_output 九项：文件/时长/分辨率/三字段/风格锁/切点不在句中/相邻段画面连贯/每段传达info_point/音频对齐 |
| ⑥ | 五（字幕） | 行宽≤180px/块高≤140px/时间轴3+采样点seek抽帧/音频对齐 |
| ⑦ | 六（封面） | vision复检色调符合预期 + 主体清晰 + 无变形乱码 + 元素到位 |

失败处理：自检失败 → 标记失败项 → 回对应阶段重做 → 重检通过才进下一步。同段连续失败 3 次 → 停下标记等用户（auto 模式同样）。

### 4.2 阶段间确认门（用户决策点）

| 门 | 位置 | 内容 |
|---|---|---|
| ① | 阶段1后 | 稿件审核（用户改稿后才进流水线） |
| ② | 阶段2 A1 后 | **创意方向卡**（2-3个视觉方案选1，NEW） |
| ③ | 阶段4后 | 分镜增强表审核（可旁路） |
| ④ | 阶段7后 | **发布前唯一闸门**（成片审核，auto 模式也停，不可跳过） |
| ⑤ | 阶段9后 | 封面审核（横竖版都要确认） |

确认卡选项统一：继续（推荐）/修改当前/切方向/跳资产/停止导出。

### 4.3 发布后核验（外部事实核验）

| 平台 | 权威判据（不能只看 exit 0） |
|---|---|
| B站 | 公开 view API `curl -s "https://api.bilibili.com/x/web-interface/view?bvid=<BV>"`（code=0；校验 title/duration/tid=21；封面 URL 下载 sha256 比对本地；-404=仍在审核稍后重试） |
| 抖音 | 作品管理页状态词：已发布/审核中/不适宜公开（敏感内容按降敏路径处理） |
| 视频号 | 后台"视频N"计数发布前后对比必须 +1（日志全绿≠已发布，SPA 假通过陷阱） |

发布节奏：B站 → 45-90s → 抖音 → 45-90s → 视频号。失败平台单独补发，不重跑全流程。
