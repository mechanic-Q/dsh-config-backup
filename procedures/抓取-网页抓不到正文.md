# 抓取-网页抓不到正文

> **触发**：web_fetch 返回 `DeepSeek API error (HTTP 404)` / 30s 超时 / 正文 <500B 只有导航 / 目标站是 raw.githubusercontent.com、知乎、linux.do、Reddit、B 站视频页
> **验证**：返回体 >2KB 且含正文段落（不是导航文字）；否则换下一条腿

## 首选

按**盲区不重叠**的顺序换腿，别对同一条重试：

1. **AnySearch extract**（免 key，中文站与文档站最强）
```bash
curl -s -m 45 -X POST https://api.anysearch.com/v1/extract \
  -H 'Content-Type: application/json' -d '{"url":"<URL>"}'
```
返回 `data:{url,title,content,content_trust}`。

2. **本机 crawl4ai**（Docker Desktop 起着才通）：`localhost:11235`，Bearer token 在 `D:\SynologyDrive\LMR\Docker\crawl4ai\.env`。

3. **Jina Reader**（必须带 key）：
```bash
curl -s -m 45 'https://r.jina.ai/<URL>' -H "Authorization: Bearer $JINA_API_KEY"
```

4. **直连 + 浏览器 UA**（前三条全空时）
```bash
curl -sL -m 45 -A 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/131.0.0.0 Safari/537.36' '<URL>'
```

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 裸用 r.jina.ai（不带 key） | 本机 IP 信誉已被拦：`{"code":401,"status":40103,"message":"You have been blocked from performing anonymous queries due to bad IP reputation."}`。2026-08 时还免 key 可用 |
| 对同一 URL 重试 web_fetch | 同一通道同一结果 |
| 公共 SearXNG 实例（searx.be 等） | 被 anti-bot 挡，返回「Verifying your browser…」 |
| AnySearch extract 抓知乎 / raw.githubusercontent.com | 422 `{"error_code":"extract_failed"}`，换 Jina 或直连 |
| Reddit / B 站视频页 | 任何通道都只给 ~479B 简介，不作证据源 |

## 注意

- 两方横评基线（2026-10-21 实测 6 个 URL）：**crawl4ai 5/6、AnySearch 4/6**，失败集合不重叠 —— 这就是必须叠两条腿的原因，不是「哪家更好」。
  - AnySearch 盲区：**知乎 422**；crawl4ai 盲区：**linux.do anti-bot**。
- **crawl4ai 要带 `"magic": true` + `Authorization: Bearer <token>`**，否则知乎返回 403、未授权返回 `Authentication required`。
- ⚠️ **raw.githubusercontent 先确认分支名**：`main` 与 `master` 不同，404 会被误判成「抓取失败」（本机踩过）。
- `tools.web_fetch` 走官方 DeepSeek Fetch API，是三家里最弱的一档。
