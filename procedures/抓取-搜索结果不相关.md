# 抓取-搜索结果不相关

> **触发**：web_search 中文 query 结果偏题 / 全是营销聚合站 / 只回 8 条 / 找不到一手源只有二手转述
> **验证**：命中 ≥1 条一手源（github.com、registry.npmjs.org、官方 docs 域名），或出现 ≥2 个互不引用的独立域名；都不满足就换通道

## 首选

1. **能直读就别搜**（这些答案搜出来是二手，环境里是原文）：
```bash
curl -s https://registry.npmjs.org/<pkg> | head -c 2000   # 版本、peer、发布时间
```
解包看 `lib/*.js` 查实现；「装得上吗」直接真装一遍到隔离 profile。

2. **换 AnySearch REST**（中文覆盖明显好于 Tavily/Brave/官方通道，实测 1.2–2.0s）：
```bash
curl -s -m 45 -X POST https://api.anysearch.com/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"...","max_results":15,"language":"zh"}'
```
多角度就多发几次；MCP 端有 `batch_search`（一次最多 5 条 query）。

3. **要垂直域**：AnySearch MCP 先 `get_sub_domains` 查可用域，再带 `domain`/`sub_domain` 搜。

## 别再来

| 弯路 | 为什么不通 |
| --- | --- |
| 同一 query 加关键词重搜 | 同一 provider 同一索引，只会更窄 |
| 指望调大 searchMaxResults | 本机已设 15，实测仍回 8 条 —— 瓶颈在 provider 侧 |
| 用官方 web_search 做穷举盘点 | 每次是一整轮 Messages 模型调用，烧 token、结果回灌上下文，条数还少 |

## 注意

- 官方搜索通道**不是搜索 API**，是一整轮模型调用（`@deepseek-ai/dsh-web-search-deepseek` 内只有 `api.deepseek.com/anthropic/v1` 与 `messages`）。
